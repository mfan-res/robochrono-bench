## run3 —— `time` 换口径后重跑（2026-08-21）

`time` 从「一个视频一组、一次问完」改成**一题一问**（D-65 / A-7）。
改的理由不是性能：分组只为省媒体开销，而能力定义里从来没有「一次回答 N 道题」
这一条 —— 它却成了 RynnBrain-2B 参加考试的门槛（1,340/1,390 输出空）。

三个模型 × 六族，1,390 题各跑一遍，**14.9 GPU-小时**。

| 模型 | 旧口径 | **新口径** | mean_tIoU | 答上来 | errors |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3-VL-8B-Instruct | 0.313 | **0.299** | 0.332 | 1390/1390 | 0 |
| RynnBrain-2B | 0.004 | **0.143** | 0.188 | 1368/1390 | 22 |
| SenseNova-SI-1.1-InternVL3-2B | 0.000 | **0.000** | 0.003 | 1330/1390 | 60 |

**time 现在可比了，而且区分得开** —— 这是七个题型里第三个有实质区分度的。

### 三个方向不同的结果

**一 · RynnBrain 从「没测到」变成真实分数。** 答上来率 3.6% → 98.4%，
`tIoU@0.5` 0.004 → 0.143。它比 Qwen 差，与它在其余题型上的排位一致。
**改之前那个 0.004 什么也不是。** 剩下 22 个错集中在 pen_inbox（13%），
已由 `✗` 标出。

**二 · 分组的便利只值 1.4 个百分点，而且只在大组上。** Qwen 0.313 → 0.299，
逐族看规律很干净：

```
族             旧      新      变化      组大小
wash         0.315  0.255   -6.0pp      12.9
tea          0.462  0.496   +3.4pp       6.0
airpods      0.005  0.000   -0.5pp       5.0
stack_cubes  0.215  0.225   +1.0pp       4.0
gift_inhand  0.111  0.122   +1.1pp       3.0
pen_inbox    0.738  0.752   +1.4pp       3.0
```

**只有 wash 明显掉了，而它的组比第二名大一倍还多。** 其余五族小幅上升。
这正面证实了披露第 5 条的担心：分组确实给了排除法的便利，
**便利大小随组大小走**。旧口径下 wash 的 0.315 里约 6 个百分点是这么来的。

**三 · SenseNova 仍然是 0，而且推翻了一个假设。**
它这次答上来了（1,330/1,390），分数还是 0.000。查预测值：

```
pred_end 中位 0.050    最大 29.1    85% 的预测 <= 1.0
而提示词里明确写着：The video is 62.5 seconds long; answers must fall inside [0, 62.5].

预测  0.010-0.050    真值  17.00-20.70
预测  0.000-0.050    真值   3.67- 9.37
预测  0.010-0.060    真值  78.33-80.03
```

**它输出的是 [0,1] 归一化坐标，而时长已经明明白白告诉它了。**

D-61 修「提示词不给视频时长」时的推理是：模型只看到抽帧、无从知道整段多长，
所以退回输出比例。**那个推理合理，但实测不成立** —— 告诉它了，它照样输出比例。
所以 SenseNova 的 0 不是那三处 bug 造成的（那三处都是真 bug，也都该修），
也不是分组造成的。**它就是不做以秒为单位的时间定位。**

这正是 `extract.py` docstring 里点名的失败模式（「SenseNova 轨迹 2D 95% 用
归一化坐标而非像素」）—— 同一模型、同一毛病、换了个题型。
它的 L2 层有量级校验，本可以把这件事标成单位问题而不是让它算 0 分。
见 cleanup_checklist 的 5.2。

## probe —— API 模型：思考值多少分（2026-08-22）

`qwen3.8-max`，每题型抽 3 题 × 6 族 = 126 题，开思考与关思考各跑一遍。
**这是第一个强模型对照点** —— 此前三个模型是 2B / 2B / 8B。

### 先修了一个缺陷才跑得成

`thinking: disabled` 写在配置里，但**从没发给服务端** —— 它卡在
`send_thinking` 这个默认 `False` 的开关上。结果 meta 记「disabled」，
服务端却在做长思考（reasoning 占 completion 的 **99%**，单题到过 8,148 token）。
这是第三次撞上同一个模式：**算出来 → 记进元数据 → 没送到执行方**
（前两次是抽帧档位 A-1、frames 派生键 A-6）。

⚠ **`max_tokens` 拦不住思考**：实测设 512 时 completion 仍到 8,191 ——
推理 token 不计入该上限。省成本只能靠关思考本身。

修法：新增 `thinking_param` 由 provider 声明参数名（DashScope 是顶层
`enable_thinking`，GLM 是 `thinking:{type}`，vLLM 是 `chat_template_kwargs`），
并把 `max_tokens` 补进 payload。四个候选参数实测都能关掉，取官方文档写明的那个。

### 结果

| 题型 | 开思考 | 关思考 | 思考值 | Qwen3-VL-8B | 输出 tok 开→关 |
| --- | ---: | ---: | ---: | ---: | ---: |
| understanding | 94.4% | 94.4% | **+0.0** | 78.4% | 625 → 52 |
| planning | 38.9% | 38.9% | **+0.0** | 29.3% | 1,832 → 58 |
| time | 72.2% | 55.6% | +16.7 | 29.9% | 2,111 → 135 |
| planning_2 | 44.4% | 27.8% | +16.7 | 26.6% | 1,377 → 134 |
| image_in_video | 100.0% | 72.2% | +27.8 | 74.1% | 1,570 → 499 |
| step_order | 77.8% | 38.9% | +38.9 | 30.2% | 6,047 → 131 |
| left_right | 77.8% | **16.7%** | +61.1 | 32.8% | 3,270 → 806 |
| 合计（n=126） | 72.2% | 49.2% | +23.0 | — | 2,404 → 259 |

**思考不是均匀加成，三类题型性质完全不同：**

- **思考无用**（understanding / planning）—— 一分不差。而且**关了思考仍明显高于本地模型**，
  说明那是实打实的视觉能力差异。此前担心「强模型是靠推理绕过 planning 的陷阱」，**不成立**。
- **中度加成**（time / planning_2 / image_in_video，+16.7 ~ +27.8）
- **决定成败**（step_order +38.9、left_right +61.1）。
  `left_right` 关掉思考只有 **16.7%，低于随机基线 25%**。

step_order 那个悬着的问题也答了：77.8% 里约四成靠思考、六成靠视觉
（关掉后 38.9%，仍远高于三个小模型的 26–30%）。

### 所以两个都跑

`plan.json` 里现在有 `qwen3.8-max`（关）与 `qwen3.8-max-thinking`（开）——
**同一个模型的两种条件，不是两个模型**。任何单一口径都会丢掉上面那张表的信息。
成本可控：关思考那轮的输出 token 只占 10.8%（全量外推 24.5M → 2.6M）。

### ⚠ 这轮更正了前面三个结论

首轮/次轮只有小模型时，我把几处低分归给了题目设计。有了强模型对照之后：

```
step_order    三个小模型 26–30%，曾判「几乎没区分度」  → 强模型 77.8%，跨度 51.6pp
planning      曾判「陷阱题，题目废了」                → 强模型 38.9%，且不靠思考
time/airpods  曾判「段太短，指标下无解」              → 强模型 72.2%
left_right    曾判「捷径没兑现」                     → 强模型 77.8%
```

**七个题型全部有区分度，一个没废。** 低分是小模型不会做，不是题目有问题。

## 这一轮学到的四件事

### 1 · planning 是陷阱题：认得越准，答得越错

| 模型 | understanding | planning 答对 | 答成「当前动作」 | 当前动作在选项里时被选中 |
| --- | ---: | ---: | ---: | ---: |
| SenseNova-2B | 40.9% | 24.1% | 27.0% | **48.2%** |
| RynnBrain-2B | 68.3% | 24.5% | 38.7% | **69.0%** |
| Qwen3-VL-8B | 78.4% | 29.3% | 38.9% | **69.5%** |

随机应为 25%。**识别当前动作的能力几乎完全转化成了「把当前动作说出来」的冲动，
而 planning 的分数几乎不动。** 三个模型答成「现在」的比例都高于答对「接下来」的比例
—— 它们在稳定地回答一个没被问的问题。

成因是算术，不是 bug：干扰项取自本族真实动作，而三动作的族里
四选一 = 答案 + 全部其余动作。详见 `docs/disclosures.md` 第 1c 条。

### 2 · time 的分数由标注段有多长决定，跨族不可比

（下表用的是 run2 的旧口径数据；run3 换口径后各族分数只小幅变动，
airpods 仍是 0，结论不变。）

`tIoU@0.5` 要求纯平移 `s ≤ D/3`。Qwen3-VL-8B：

```
族             真值段 D   允许平移 D/3   实测平移中位   够不够   tIoU@0.5
airpods          1.8s        0.6s         6.5s      ✗       0.5%
wash             4.8s        1.6s         3.2s      ✗      31.5%
pen_inbox        6.8s        2.2s         1.2s      ✓      73.8%
gift_inhand      9.7s        3.2s         4.5s      ✗      11.1%
stack_cubes     12.1s        4.0s         4.6s      ✗      21.5%
tea             12.4s        4.1s         4.3s      ✗      46.2%
```

**模型的时间精度大致恒定（3–6.5 秒），而允许的误差随段长从 0.6 秒变到 4.1 秒。**
中心命中率 40.6%–87.9%（airpods 除外 9.0%）—— 它找对了大致位置，输在边界。

**airpods 在当前指标下实质是无解题**：段长 1.8 秒，要求 0.6 秒精度，
比标注本身的精度还高。它的 0.5% 不是模型差。

### 3 · RynnBrain 的 time 是框架故障，不是能力（**已修，见 run3**）

跑之前的冒烟就发现了，并做了可证伪的预测：**预测全空 1390/1390，实际 1340/1390（96.4%）**。

逐步排除（每步都是实测）：

```
8 / 16 / 32 帧全部输出空          → 不是抽帧数
每 unit 跑满 21.7 秒              → 不是 OOM
去掉 system_prompt 照样空         → 不是「只返回一个 JSON」与「每行一个」的冲突
time 视频 + und 词 → 正常出话     → 与视频无关
und 视频 + time 词 → 空           → 是提示词
1 道题 → 172 字符；2 道题 → 0 字符 → 断点在题数
```

而 time 是「一个视频一次问完」，**249 个 unit 里 0 个只含 1 道题**。
即使只问 1 道，输出也是 `{"start": <14.0>, "end": <27.0>}` —— 把占位符的
尖括号照抄出来，不是合法 JSON。

**已修**（2026-08-21，D-65）：改成一题一问，答上来率 3.6% → 98.4%，
`tIoU@0.5` 0.004 → 0.143。见 run3。
「代价是媒体重复传输」这个当时的估计**是错的** —— 实测每次调用
`= 4.1s 固定 + 4.17s × 题数`，固定开销只有 4.1 秒，生成才是大头，实际代价 1.47×。

### 4 · ~~三个题型没有区分度~~ **已被 probe 推翻（2026-08-22）**

> **当时的观察仍然成立，结论错了。** `step_order`（4.0pp）、`planning`（5.2pp）、
> `planning_2`（2.3pp）在三个模型之间确实几乎不动 —— 但那三个是 2B/2B/8B。
> 强模型上 step_order 77.8%、planning 38.9%，跨度分别变成 51.6pp 与 14.8pp。
> **它们不是没有区分度，是那三个模型都做不了。**

已有披露里的两条**事实**仍然成立（它们是从数据算出来的，与模型无关）：
`step_order` 有 83% 的题可以靠固定流程查表（第 1b 条）、
`planning` 的选项里通常包含当前动作（第 1c 条）。

**但「所以题目废了」是推论，不是事实**，而且推错了。
判据在于：捷径**存在**是数据可证的；捷径**足以让题目失效**必须有强模型才能判。
这两句话我当时缝成了一句。

~~**这三个题型共 3,494 道、占题量 34%，产出的信息量接近零。**~~
**这句话是错的** —— 见上。教训写在下面。

## 读之前

**跨族不可比**，按设计如此：每个族的难度按它自身的数据校准。
`time` 还额外受段长支配（见上）。

盲基线已经证明这些题不看视频拿不到分（`left_right` 25.0%、
`image_in_video` 21.5%、`step_order` 上界 28.8%）。
