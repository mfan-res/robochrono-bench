### `robochrono` 的结构

一次模型调用 = 一个 `Unit`。多数任务一题一次调用，**`time` 是一个视频一次调用**
（回答该集的全部问题），`Unit` 把两种形态统一起来。

任务只需实现四个钩子：取媒体 / 组 prompt / 解析输出 / 算分。
其余约 1,600 行样板由 `engine` 统一承担。

## 迁移时改了什么

**只改了三处，都是口径不是行为。**

**一 · 夹具替代完整数据。** 回归本来读 `eval/datasets/QA`（141 MB，不含 trajectory）
与 `eval/results/baseline`。但回归是「拿录好的模型输出重放、比对新旧实现的打分」——
它只用 baseline 里出现过的那些 id，**整份 QA 里其余 2,570 道从来没被读到**。
裁成 `fixtures/`（130 道题 + 基线，3.7 MB）之后回归在本仓库内自足。
路径统一在 `tests/paths.py`，六个测试不再各写各的。

**二 · 媒体路径按文件名比，不按绝对路径。** 基线是在旧仓库录的，绝对路径必然不同。
**没有直接忽略路径** —— 那会掩盖「切错了片段」这类真错误；
改成比文件名，文件名里带着族/集/帧号，切错了照样能发现。

**三 · 缺数据时显式跳过。** `normalized` 那一套需要完整 v1 QA 才能构建产物，
`request_equivalence` 需要真实媒体。两者都改成**打印原因并跳过**，
而不是静默通过或报错。

## 与 ④ 出题的接口

④ 的产物是 `data/vqa/items.jsonl`，走的是新契约（`prompt` / `truth` / `provenance`）。
**评测端读的仍是 v1 的字段**（`question` / `options` / `answer` / `input.clip_path`）。

两者由 **[7] pack** 衔接 —— 它把 `items.jsonl` 投影成评测端要的形状。
干净的契约留在 `items.jsonl`，适配消费者是 pack 的职责，
**评测端因此不用改，它这六套回归也就仍然有效**。

## 还没定的
