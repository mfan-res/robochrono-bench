# robochrono-bench

机器人操作视频的 VLM 评测基准。从原始录像出发，经人工标注、自动出题，
到模型评测与结果解读，全流程自建。

这是对前一版项目的重构。重构的起因不是代码不好看，而是**上一版有一批影响分数的问题，
且它们全都不报错** —— 六个族的题目难度与设计意图不符、正确答案会被判错、
不看画面只量视频时长就能超过基线。这些问题的共同点是：
**每一层单独看都讲得通，组合起来出错，而没有任何一层会报警。**

## 七段流水线

```
① 能力定义 ──▶ ② 采集 ──▶ ③ 标注 ──▶ ④ 出题 ──▶ ⑤ 验题 ──▶ ⑥ 评测 ──▶ ⑦ 解读
                  ▲          ▲          ▲          │                      │
                  └──────────┴──────────┴──────────┘                      │
                        验题不过，回上游修                                   │
                  └────────────────────────────────────────────────────────┘
                        解读发现混淆变量，回题型或采集
```

**上一版实际只有 ②③④⑥ —— ⑤ 验题与 ⑦ 解读完全缺失。**
我们踩过的每个问题，都能定位到「某一段缺了验收」。

| 段 | 状态 | 目录 | 说明 |
| --- | --- | --- | --- |
| ① 能力定义 | 沿用 | — | 七个题型继承自上一版，已砍掉 trajectory。**理由尚未成文** |
| ② 采集 | ✅ 完成 | `data/raw` `data/source` | 不可重来。分辨率/叠加/命名已对齐，遗留项已披露 |
| ③ 标注 | ✅ 完成 | `src/label` `data/label` | 全量六项核验；标注器重做为本地网页版 |
| ④ 出题 | ⬜ **下一步** | `src/vqa` | 从 raw + label 自己生成，不沿用上一版产物 |
| ⑤ 验题 | ⬜ 新建 | — | 盲基线、答案唯一性、难度分布 |
| ⑥ 评测 | 🔶 已有实现 | `src/eval` | 在旧仓库，含冻结参考实现与六套回归，待迁入 |
| ⑦ 解读 | ⬜ 新建 | — | 混淆变量披露、跨族可比性说明 |

**越往上返工越贵。** ②③ 已固化，真正能掌控的是 ④ 往后。

## 四条从事故里长出来的原则

不是风格偏好。每一条背后都有一次真实的、代价不小的错误。

### 1 · 一个东西只存一份，其余都是引用

同一个动作曾经在系统里被存了 **11 份**（词表、叙述、动词、宾语、
出题产物里的答案文字、选项、题干内嵌、LLM 缓存的键……）。
**已知的五个事故，全部是其中两份漂移造成的。**

现在文字只存在于 `subtasks.json` 一处，别处一律存 ID。
**ID 一旦分配就永不改变** —— 改措辞只动一行，所有引用自动跟随。

### 2 · 派生物不许回写进源头

上一版把出题器算出的时间窗口写回了人工标注层。于是下一轮出题把上一轮的参数
当成了人工真值，错误被固化第二次；而且它抹掉了原始信息
（幸亏还留着一份 `original_*` 才得以还原）。

schema 现在**显式拒绝**出题产物出现在标注里。

### 3 · 判据要写成机器能执行的，并在边界上强制

我们踩的每个坑都是**隐式契约** —— 两个环节之间存在约定，但没写下来、
也没有任何东西检查它，于是违反时不报错，只是结果悄悄变了。

现在每个层间边界都有 schema + 校验器（`src/common/schemas/`）。
**校验器一套代码，产出时与离线核验共用** —— 曾经两边各写各的判据，
结果一个族显示「齐全」而实际缺了一集。

### 4 · 缺失要显式，不要静默跳过

「找不到就跳过」制造的是**看起来正常、实际少了东西**的结果。
解析不到、覆盖不全、疑似异常的，一律进报告。

## 上手

```bash
pip install numpy pyarrow jsonschema        # 另需 ffmpeg / ffprobe

python3 src/label/validate.py               # 标注六项核验（应报 64 条，见下）
python3 src/label/tests/test_core_replay.py # 语义回归（不需要视频）
python3 src/label/serve.py --port 8000      # 网页标注器
```

`validate.py` 报的 **64 条不是 bug，是待决策项** ——
全部是数据固有、不可用工程手段消除的：

```
tea2    20 条   视频是多集打包的，只标了第一个 episode
express  2 条   同上（该族已退出）
wash    40 条   每集重复动作 —— 洗两个盘子，同一动作做两遍
可疑     2 条   一个零长度标注段，疑似连按了两次
```

**这个数字是基线。变多说明改坏了；变少多半是把检查弄失效了。**

## 决策记录

**`DEVLOG.md` 是这个项目最重要的文档**：30 条决策、7 条问题记录，
以及一节**「被推翻的判断」**。

那一节记着我们先错后纠的每一次 —— 包括好几回「用一个自洽的观察给算术产物编故事」：
看到画面里机械臂正在撤离，就断定那个空隙是标注员有意留的；
实际它是上游一个默认参数的算术后果，而画面之所以吻合，
是因为那个参数本来就是照着画面调的。

**只留结论的话，下一个人会重新踩一遍。** 所以判断被推翻时不删原文，
改写成「曾经认为 X，实测是 Y，怎么发现的」。

> 文中引用的 `docs/figures/…` 不在仓库里（40 MB，占 97%，已 gitignore），
> 留在产出这些决定的机器上。
